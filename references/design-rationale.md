# 需求采集技能的适配依据

适用目标：GPT-6 Astra。查阅日期：2026-09-14。
本页用于维护技能，不是每次需求采集的必读材料。

## 当前官方来源

- [Astra 提示指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra#prompting-best-practices)：明确自主推进、澄清边界、技能指令冲突、表达、委派与验证范围。
- [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)：Eric Provencher，2026-09-11；简洁触发描述、按需读取、重审旧流程和定义完成条件。
- [Build skills](https://learn.chatgpt.com/docs/build-skills)：聚焦任务，明确输入输出，渐进式加载，并检查触发行为。

这些是官方指导的摘要，不代表全部建议必须转成强制步骤。社区关于低推理
档位和上下文连续性的个例不足以证明本工作流收益，本次不据此更改模型配置。

## 本技能中的取舍

| 类型 | 决定及原因 |
|---|---|
| 官方原则的应用 | 入口区分新建、续办和只验证；详细流程与维护依据按需加载。 |
| 官方原则的应用 | 用证据驱动关键追问，沿用用户已明确的选择；遇到局部阻塞继续不依赖它的工作。 |
| 官方原则的应用 | 最终批准后完成冻结和复验，不在初版摘要或批准标志处提前交付。 |
| 用户与项目约束 | 保留洁净室材料隔离、来源追踪、接口语义完整性和最终明确批准；模型能力不能替代这些要求。 |
| 本地设计判断 | 默认提示不再鼓励反复确认；设计树只用于真实依赖；验证按变化及阶段触发。 |
| 本地设计判断 | 保留确定性采集、校验和哈希脚本，不用自然语言承诺替代摘要绑定与结构检查。 |

续办从产物恢复状态；保留既有批准记录，不允许为修订技能而修改真实算子
契约或材料。按所在项目的委派与模型策略执行，技能不硬编码某个推理档位。

## 维护时核对

实质性修改时实际查阅用户指定或任务实际使用模型的当前官方指南及技能
规范；记录来源、模型、日期及未核实项。模型切换时只重审受影响的规则，
不擅自替换模型或修改其他技能。普通采集执行无需为此再次联网。

验证应覆盖：明确选择后的新建、带历史决策的续办、局部证据冲突、只验证、
最终批准后的冻结及复验、洁净室受限材料。检查实际行为与产物，不把标题
或关键词匹配视为行为通过。静态校验和隔离试用均不等于真实算子或 NPU 验证。
